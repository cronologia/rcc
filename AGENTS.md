# AGENTS.md

Operating guide for AI coding agents (and humans) working in this repository.
Read this and `context.md` before making changes. The shared method lives in
`cronologia/core`; its skills are **vendored into this repo** at
`.claude/skills/` (generated — see "Skills" below). Family-wide architecture
rationale lives in `cronologia/core/adr/`; this repo's own decisions in
`adr/`; the original per-project rationale in `cronologia/fsp` → `docs/adrs/`.

## What this project is

A compiled static website documenting the chronology of the **Catholic
Charismatic Renewal (RCC)** — global origins plus the Brazilian movement.
A single JSON file is the source of truth; a zero-dependency Node script
compiles it into static HTML served by GitHub Pages. Built from the
`cronologia/core` template — see `adr/0001-*.md` for what was actually
adopted.

## Sourcing rules

**The binding rule set is the `sourcing-rules` skill**, vendored at
`.claude/skills/sourcing-rules/SKILL.md` (canonical in `cronologia/core`).
Load it before touching `data/chronology.json` or writing any site copy.
In one line: cite it or flag it; attribute, don't assert; sources span the
spectrum by design; date every time-sensitive status; testimony and video are
perspectives, not fact sources.

## Agent-side tooling (in `cronologia/core/tools/`)

Python 3 stdlib, run from a checkout of `core`. These are for agents; the
build itself stays zero-dependency Node.

- `dataset-query.py` — **query before reading whole files.** Returns locators
  and slices of `data/chronology.json` (events, references, `refs
  --unarchived`) instead of forcing a whole-file read.
- `unverified-report.py` — lists everything flagged unverified, undated or
  thinly sourced; the working queue behind the gaps listed in `context.md`.
- `mine-prep.py` — prepares transcripts for mining (pairs with `mine-video`).
- `xref.py` — cross-repo consistency for entities shared with sibling repos;
  run it whenever a shared person, body or date is touched.

## Operational loop

```bash
node scripts/validate-data.js && node --test && node build.js
```

Then commit `data/` **and** the regenerated `docs/` in the same change — CI
fails if `docs/` drifts. `archive-refs.js` and `check-links.js` are
out-of-band / CI only: the build never touches the network.

## Working agreements

1. **Edit data, not output.** Change `data/chronology.json`, run
   `node build.js`, commit the regenerated `docs/` in the same change.
   `docs/` and `data/archives.json` are generated — never hand-edit them.
2. **Keep the build green.** `node scripts/validate-data.js`, `node --test`
   and `node build.js` must all pass; CI fails if `docs/` drifts.
3. **Cite every fact; flag every uncertainty; attribute every contested
   characterization.** The validator enforces non-empty `sources[]`.
4. **A merged PR is finished** — branch fresh from `main` for new work.
5. **One repo, one committer per wave.** Don't edit a sibling repo's data
   from here — cross-reference it instead.

## Data quality & sourcing rules

Beyond the family's five core rules: label movement sources (RCC Brasil,
Canção Nova, CHARIS, ICCRS) as such and never let them carry a contested
claim alone; membership/attendance numbers are the movement's own — always
"according to the movement"; record the 1969-vs-1972 Brazil-arrival
divergence instead of resolving it; use the Vatican's "new service, not
fusion" formulation for CHARIS; sociological framings (Prandi's
'pentecostalization', competition with CEBs) are attributed to their
authors and cross-linked to the tl project, not argued here.

**Contested numbers are never silently unified.** The `numbersChart` block
draws each series on its *own* axis, with its *own* unit and its *own* source
label, under a required `unitNote` banner stating that the series are not
directly comparable. A movement self-report and an external survey never
share a scale. See `adr/0001-*.md`.

## Family map and this repo's boundaries

The interdependency map for the whole family is
`cronologia/core/DEPENDENCIES.md`. What it means here:

- **`core`** — this repo *consumes* the template, skills and tools; it never
  edits `core`. Renderer/validator fixes flow **up** to `core` first, then
  back down via `adopt-template`.
- **`tl` (liberation theology / CEBs)** — the standing boundary. The
  "conservative renewal", "pentecostalization" and RCC-vs-CEBs framings are
  **tl's** subject. Here they are attributed to their authors (Prandi,
  Carranza, Pew) and cross-linked — **cross-link, don't argue**, and don't
  duplicate tl's dataset.
- **`fsspx`** — Catholic traditionalism; a peer that may cross-reference
  shared Vatican documents and dates. Peers cross-reference, never duplicate.
- **`archive`** — sources cited by two or more projects belong in
  `cronologia/archive` (its ADR-0001); single-project sources stay local. The
  archive is private: reader-facing citations are the original URL plus its
  Wayback snapshot, never a raw archive URL.
- **`glossary`** — this repo does **not** consume glossary term ids yet; its
  copy carries no `[[term-id]]` cross-links. Adding them would be a new
  change, not an existing capability.
